# 目录设计

WindPlay 采用轻量的多作品仓库结构。`works/` 表达“可以直接体验的网页作品”，比按技术栈
分类更稳定：点云工具、Canvas 动画、WebGL 艺术和小游戏都可以拥有不同实现，但对访问者来说
都是作品。

## 边界

- `works/<name>/`：一个可独立开发、测试和发布的作品，并包含 `demo/index.html` 成品入口。
- `docs/`：影响整个仓库的设计决策和维护说明。
- `.github/`：仓库自动化，不放作品运行时代码。
- `packages/`：暂不创建。出现至少两个真实消费者后，再用于稳定的共享代码。

根 `package.json` 只负责 npm workspaces 和统一命令，不承载浏览器运行时依赖。根锁文件保证
所有 Node.js 作品可以通过一次 `npm ci` 得到可重复的开发环境。

`demo/index.html` 是仓库浏览者可直接打开的完整单文件成品，需要提交到 Git。`dist/` 保存构建
产生的其他格式和中间交付物，由 `.gitignore` 排除。两者都由构建脚本生成，不能手工修改。

## 演进原则

新实验先作为一个独立作品进入 `works/`。当作品间出现重复实现时，先确认它们的需求和变化
节奏相同，再提取共享模块。若未来需要统一作品展厅，应把展厅作为真实应用加入，而不是让根目录
逐渐承担隐式的前端职责。
